# Image metadata workflow

`seo-injector.py` uses `seo-images.json` as the reviewed source of truth for the
public article images, scientist portraits, avatars, social preview, and brand logo. Descriptions follow the existing image
source inventory in `frontend/public/images/LICENSES.md`; generated illustrations
are identified as AI-generated. Unused demo author portraits are excluded.

From the repository root, with Python 3.10+:

```powershell
python -m pip install -r requirements-seo.txt
python seo-injector.py
python seo-injector.py --webp --apply
python -m unittest discover -s tests -p test_seo_injector.py
```

The default command validates the entire batch without writing files. `--apply`
backs up each changed original in `.seo-backups/` and writes atomically per file.
Backups are keyed by the original file's SHA-256 and are excluded from Git.
An interrupted write can be rerun; this is not a transaction across all files.
Repeated runs with unchanged descriptions produce identical bytes.

JPEG files receive EXIF Windows Title, Subject, Keywords, Comments and credited
Author, including Unicode terminators. PNG files receive UTF-8 iTXt in the normal
mode. `--windows-compatible` converts PNG/GIF/WebP assets to high-quality JPEG,
backs up the source, migrates manifest URLs, and removes the superseded public
copy after the JPEG is safely written. Existing JPEG scans are copied unchanged;
conversion retains dimensions and color profiles, and flattens transparency on
white. `--webp` converts the catalog to quality-90 WebP with method 6, preserving
dimensions, ICC profiles and embedded EXIF metadata. Windows Explorer may not
display WebP EXIF fields even though they remain inside the files. No images are
downloaded.

`frontend/src/lib/image-metadata.json` is generated by `--apply` and must be
committed with any manifest changes. The frontend uses it for contextual alt
text, image dimensions in social previews and ImageObject structured data.
Article pages publish Article/WebPage and breadcrumbs; scientist pages publish
ProfilePage/Person. The sitemap includes image URLs. JSON-LD is rendered on the
server and escapes `<` before embedding.

To add a photo, add its `/images/...` path and accurate `title`, `description`,
`alt`, and `keywords` to the manifest. Optional `source`, `creditText`, `creator`,
and `license` must reflect the actual source; do not substitute ScienceHub as
the photographer of third-party work. Only add a license URL when verified.
The script accepts `--manifest`, `--public-root`, `--catalog`, and `--backup-dir`
for processing a separate batch. GIF descriptions are available to the website,
not Windows file properties.

## Production setup

The canonical origin defaults to the confirmed `https://scienceknowledgehub.com`.
`NEXT_PUBLIC_SITE_URL` can override it before building/deploying; production must
use the public HTTPS origin, not localhost. After deployment, validate pages with
Google's Rich Results Test and submit `/sitemap.xml` in Search Console. The
current sitemap enumerates the local curated content; API-only content needs a
separate content-list integration before its URLs can be included automatically.

Next.js optimized image variants can strip embedded metadata, which is why the
page-level descriptions and structured data are also provided. Embedded EXIF
keywords are not a ranking guarantee. GEO here means making published content,
entities and images understandable to generative search, not adding GPS tags.
